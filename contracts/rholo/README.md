# rholo bridge contract

## Phase 1 demo (implemented)

The demo is a single `Bridge` contract plus two inlined libraries:

- `src/deploy/00_bridge.rho` — installs the bridge, registers it with
  `rho:registry:insertArbitrary`, and defines the arms:
  `balanceOf`, `asset`, `fees`, `withdrawal`, `pendingWithdrawals`, `config`,
  `transfer`, `mint`, `burn`, `completeWithdrawal`, `admin`.
- `src/lib/Guard.rho` — m-of-n secp256k1 verification over a 32-byte digest.
- `src/lib/Ledger.rho` — REV-address identity, balances, fee math.
- `build/00_bridge.rho` — generated by `tools/build_contracts.py` (committed; do not
  hand-edit).

The installer renders the network, bridge id, admin/relayer sets and asset registry via
`harness/render.py`. The contract returns its registry URI on `rho:rchain:deployId`.

The demo is deliberately one state cell. The production target is the split described
below; the single contract validates the attestation, ledger, fee and governance flow
before that split is made.

## Target production suite

- `BridgeRoot.rho` — installer-gated singleton: 2-of-3 admin, relayer set and threshold,
  asset registry, fee/cap parameters, pause.
- `WrappedToken.rho` — one per asset; `totalSupply` + holder balances; public
  `balanceOf`/`transfer`; mint/burn authority held in the bridge closure, never a state
  map.
- `Bridge.rho` — mint (m-of-n attestation, idempotent), burn (destination + withdrawal
  record), fees, caps, pause.
- `Attestation.rho` — canonical message and threshold verification.

Splitting is worthwhile only once the demo's invariants and the native vaults are stable;
the wire formats (`spec/attestation.md`) do not change.

## Constraints respected in the demo

- One state cell per object; consume, validate, repost exactly once on every path.
- No `select`; block-height deadlines; 56 KiB budget (measured 15.5 KiB).
- Every mutating arm checks idempotency first; every value-moving path has a
  conservation test; every refusal path reposts the cell.
- Amounts are `i64` rholo base units; the demo uses USDT 6 decimals and ETH 8.
- Burn remains available while paused; mints fail closed.

## Tests

`make demo` runs the behavioural suite on a local devnet: install, config, asset lookup,
valid mint, replay, below-threshold, unknown asset, burn, withdrawal completion,
transfer, pause/unpause, and conservation. See `harness/README.md` for what is not yet
covered.
